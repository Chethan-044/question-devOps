# Part 12: Monitoring, Metrics, and Logging

---

## Q55. What is Prometheus?

**🔑 Keywords:** time-series database, pull/scrape model, metrics collection, PromQL, Alertmanager, TSDB, dimensional data

**Beginner-Friendly Answer:**
Prometheus is like a fitness tracker for your servers and applications. Every 15 or 30 seconds, it visits all your microservices and infrastructure components, "scrapes" their vital signs (like CPU usage, memory consumption, number of HTTP 500 errors, request latency), and stores those numbers over time in a time-series database. You can query this data using its query language, PromQL, and send alerts if numbers cross safe limits.

**Detailed Answer:**
Prometheus is a monitoring system that collects and stores time-series metrics.

Metrics can include CPU usage, memory usage, request counts, latency, and application-specific measurements.

In our architecture, Prometheus is intended to monitor Kubernetes and application workloads.

### Cross-question: What is the difference between metrics and logs?

Metrics are numerical measurements over time.

Logs are timestamped records of events or messages generated by applications and infrastructure.

For example, a metric may show that an application has a high error rate, while a log entry may explain that a downstream request timed out.

## Q56. What is Grafana?

**🔑 Keywords:** visualization platform, dashboards, panels, PromQL visualization, data source agnostic, observability UI

**Beginner-Friendly Answer:**
If Prometheus collects the numbers, Grafana is the beautiful TV dashboard that displays them. Grafana connects to Prometheus (and other data sources), turning raw numbers and queries into easy-to-read line graphs, bar charts, gauges, and heatmaps. It's what the DevOps team puts up on their monitoring screens to see the health of the entire e-commerce store at a glance.

**Detailed Answer:**
Grafana is a visualization and observability platform used to query and display data from supported data sources.

In our project, it is intended to visualize Prometheus metrics through dashboards.

### Cross-question: Is Grafana a metrics collection system?

Not primarily. Prometheus collects and stores metrics, while Grafana visualizes data from Prometheus and other supported data sources.

## Q57. What is Alertmanager?

**🔑 Keywords:** alert routing, grouping, silencing, inhibition, notification channels, Slack/PagerDuty/Email integration

**Beginner-Friendly Answer:**
Alertmanager is the notification officer. When Prometheus notices an alert rule is firing (e.g., "Product Service error rate > 5% for 2 minutes"), it sends the alert to Alertmanager. Alertmanager groups duplicate alerts so your phone doesn't get spammed with 100 messages for the same root cause, silences expected maintenance alerts, and routes notifications to the right team via Slack, PagerDuty, or Email.

**Detailed Answer:**
Alertmanager handles alerts generated by Prometheus and supports grouping, routing, silencing, and inhibition.

In our architecture, it can route alerts to configured notification channels when monitoring rules detect issues.

### Cross-question: Give an example of an alert.

An alert could trigger when the application error rate remains above a threshold for a defined duration.

Another example is when a Pod repeatedly restarts or a workload has insufficient available replicas.

## Q58. What are Elasticsearch and Kibana?

**🔑 Keywords:** ELK Stack, Beats/Filebeat, centralized logging, search engine, log aggregation, log index, Kibana discovery

**Beginner-Friendly Answer:**
When you have 20 microservices running across 10 servers, checking logs by SSHing into each box is impossible. The ELK stack solves this: Filebeat collects logs from all Pods, Elasticsearch indexes and stores millions of log lines so you can search through them in milliseconds, and Kibana gives you a search-engine-style web UI where you can type "error in order #1234" and instantly see the full stack trace from all services involved.

**Detailed Answer:**
Elasticsearch is a search and analytics engine that can store and search indexed log data.

Kibana provides interfaces for exploring and visualizing data stored in Elasticsearch.

In our architecture, the Elasticsearch and Kibana components are intended to support centralized log analysis.

### Cross-question: What is Beats?

Beats is a family of lightweight data shippers that can collect and forward supported data to downstream systems.

For example, Filebeat can collect log files and forward them to a configured destination.

The exact deployment method depends on the chosen Elastic Stack version and configuration.

### Cross-question: Why not just use kubectl logs?

`kubectl logs` is useful for troubleshooting individual Pods, but it is not a complete centralized logging solution.

Logs may become difficult to search across many services, especially when Pods are recreated and workloads scale.

Centralized logging allows teams to search, correlate, and retain logs across multiple workloads.
